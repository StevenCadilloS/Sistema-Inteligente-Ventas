# ══ 2. BACKEND (obligatorio: la app no arranca sin el) ════════════════════
#
# El catalogo, el stock y las ofertas viven en una base compartida. Sin
# credenciales la app no muestra productos: lo dice en pantalla y no arranca
# la tienda. Hay dos formas de tener esa base, y cualquiera sirve.
#
# ── Opcion A: proyecto en supabase.com (lo mas rapido) ────────────────────
# Cuenta gratuita        https://supabase.com  -> New project
# PostgreSQL 15+         lo provee el propio proyecto
# Aplicar migraciones    pegar en orden en el SQL Editor del panel:
#                          supabase/migrations/0001_esquema.sql
#                          supabase/migrations/0002_funciones.sql
#                          supabase/migrations/0003_semilla.sql
#                          supabase/migrations/0004_autenticacion.sql
#                          supabase/migrations/0005_almacenamiento.sql
#                          supabase/migrations/0006a_productos.sql
#                          supabase/migrations/0006b_escaleras.sql
#                          supabase/migrations/0006c_combos.sql
#
# ── Opcion B: PostgreSQL propio (autohospedado, sin cuentas) ──────────────
# Podman 5.x o 6.x       https://podman.io      (o Docker 24+, equivalente)
#   o Docker Compose v2
# PostgreSQL 16          se descarga solo: docker.io/library/postgres:16-alpine
#                        definido en supabase/docker-compose.yml
# psql                   opcional; si no esta, los scripts usan el psql que
#                        ya vive dentro del contenedor
#
#   podman compose -f supabase/docker-compose.yml up -d
#   bash supabase/tests/ejecutar.sh      # aplica migraciones y prueba
#
# Nota de memoria (Windows): Podman corre sobre una VM de WSL2 que, sin
# limite, puede crecer hasta el 50% de la RAM y no devolverla. Conviene un
# %USERPROFILE%\.wslconfig con:  [wsl2] memory=4GB / autoMemoryReclaim=gradual
# y detener la maquina al terminar:  podman machine stop
#
# ── Credenciales (nunca se versionan) ─────────────────────────────────────
# env.json en la raiz, copiado de env.example.json:
#
#   { "SUPABASE_URL": "https://xxxx.supabase.co",
#     "SUPABASE_PUBLISHABLE_KEY": "sb_publishable_..." }
#
# Los proyectos anteriores emiten "anon key" (un JWT) en vez de publishable
# key; se acepta igual como SUPABASE_ANON_KEY. La clave concede solo lectura:
# toda escritura pasa por funciones validadas del servidor.
